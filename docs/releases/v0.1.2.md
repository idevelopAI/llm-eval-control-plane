# v0.1.2 — Score bars, a quickstart-aligned demo, and clearer errors

A patch release of LLM Eval Control Plane. It makes release decisions easier to
read in the dashboard, aligns the public demo with the README quickstart, makes
CLI failures explain themselves, and adds newest-first paging to two API lists.
The supported workflows and boundaries from [v0.1.0](v0.1.0.md) are unchanged.

## What changed

- **Score bars.** Each gate row draws zero-based baseline and candidate bars
  with a threshold marker and a "Pass at" caption, so a regression is visible
  without reading the numbers.
- **Demo matches the quickstart.** The public demo now shows the README
  quickstart's real output: the same thresholds, names, decision digest, case
  slices, and distribution statistics.
- **Dashboard layout.** The header stays pinned while scrolling and, in local
  live mode, appears above the suite history and decision picker. An empty
  slice lens marks the selected gate as outside the lens and offers a way back
  to all gates. The suite forms, operator-guide screenshots, README screenshot,
  social preview image, and favicon use the dark design.
- **Clearer CLI errors.** `llm-eval suite` commands name the cause of a
  failure, such as a missing run, a mismatched dataset, an existing output
  path, or identical baseline and candidate runs, using only fixed messages.
- **Newest-first lists.** `/v1/runs` and `/v1/jobs` accept `order=desc`, like
  `/v1/release-decisions`. The default stays ascending. The API contract
  version moves from 1.6.0 to 1.7.0 for this addition.
- **Quieter logs.** Successful health probes are counted in metrics but no
  longer logged or traced; failed probes are still logged.
- **Dependencies and security.** Updated Python, dashboard, container, and CI
  dependencies, including FastAPI 0.162.2 and Next.js 16.4.5. The dashboard lint
  toolchain requires `minimatch` 11.0.5 (GHSA-g3hv-75wg-m249), and the Next.js
  lint-plugin security patch is ported to 16.4.5, which removes the cause of
  Dependabot's failing dashboard updates.

## Upgrading

There are no database schema, migration, or configuration changes, and no
breaking API changes. The only API change is the optional `order` query
parameter on `/v1/runs` and `/v1/jobs`. Existing deployments keep their
project ID, credential registry, and database. Refresh local environments from
the lockfiles:

```bash
uv sync --locked
pnpm --dir dashboard install --frozen-lockfile
```

Rebuild the container image to pick up the updated base images.

## Verification and distribution

The release is tagged from reviewed `main` after the required test and security
checks pass, including the Python matrix, PostgreSQL/recovery checks, dashboard
build, dependency audits, secret scanning, container scanning, and CodeQL.

GitHub's source archives contain tracked source and public synthetic fixtures.
No credentials, local evidence, diagnostic notes, backups, or private environment
files are release assets. This release does not publish to PyPI or deploy a
backend. The Python package/CLI version is `0.1.2`; the API contract version is
`1.7.0`, and artifact schemas are unchanged.
