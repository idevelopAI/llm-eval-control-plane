# v0.1.0 — Local evaluation and release evidence

The first versioned source release of LLM Eval Control Plane. It covers the
documented offline CLI, authenticated local API/worker/dashboard, and static
public demonstration. This is an early-stage, pre-1.0 release, not a claim of
production readiness or a hosted model-evaluation service.

## Included workflows

- Immutable evaluation suites pin datasets, evaluator identities, execution
  contracts, slices, and release policies under a content digest.
- Deterministic baseline/candidate comparisons enforce slice-aware quality,
  safety, regression, and coverage gates, with JSON, Markdown, and JUnit reports.
- PostgreSQL-backed jobs support leases, heartbeats, cancellation, recovery,
  and fenced evidence publication.
- The loopback-only local dashboard provides suite/target history, detailed gate
  review, and explicit offline run/comparison submission with separate read and
  write credentials.
- The bilingual 56-case DataBridge fixture evaluates text-to-SQL behavior through
  mock-response replay and a restricted read-only PostgreSQL role.
- The public Vercel demo serves static synthetic evidence without a backend,
  credential entry, or model-provider calls.

## Boundaries

The suite CLI and API v1 execute deterministic targets, not arbitrary hosted
models. Mock scores, simulated latency, and usage are not live-model benchmarks
or measured API costs. Optional DataBridge live access requires separate explicit
opt-ins and separately provisioned credentials; it is outside the default demo
and offline workflow and can incur provider charges.

One API deployment/database owns one project; this is not row-level
multitenancy. Leases fence durable evidence publication, while target invocation
remains at least once. Non-loopback operation requires additional infrastructure
and security review. Full local evidence may contain evaluation content and must
remain protected and outside Git.

No API contract, database schema, or deployment permission changes are introduced
by the release metadata. Existing deployments should preserve their project ID,
credential registry, and database; the new bootstrap is for first-time setup,
not credential rotation.

## Verification and distribution

The release is tagged from reviewed `main` after the required test and security
checks pass, including the Python matrix, PostgreSQL/recovery checks, dashboard
build, dependency audits, secret scanning, container scanning, and CodeQL.
Regression tests exercise the credential instructions without real credentials.

GitHub's source archives contain tracked source and public synthetic fixtures.
No credentials, local evidence, diagnostic notes, backups, or private environment
files are release assets. This release does not publish to PyPI, deploy a backend,
or change the public website. The Python package/CLI version is `0.1.0`; the
independently versioned API contract and artifact schemas are unchanged.
